What the original request is solving

“What did the agent change since I last looked?”

The current cumulative branch diff helps with the final review before opening a PR. The requested addition is an incremental review workflow inside the same workspace.

An agent makes several commits, starts editing again, and you inspect those new edits before walking back through each earlier commit.
Requested viewWhat it should show
All branch changesThe existing cumulative comparison with the base branch, including local edits. Preserve this workflow.
Uncommitted changesChanges since HEAD, with separate staged, unstaged, and untracked groups. Selecting a group entry shows that particular comparison.
Commit historyMessages, authors, timestamps, and short hashes. Selecting a commit shows its changed files and the patch introduced by that commit.
Safe browsingReading a past commit leaves the working tree and the running agent untouched.

What to borrow from Sublime Merge

  • A persistent, selectable history with pending work at the top.
  • A direct connection between the selected entry, its files, and its diff.
  • Visible staging boundaries, including a file that has both staged and unstaged edits.
  • Layouts that adapt to available space. This concept puts history and files above the diff in a narrow preview, and uses three columns when expanded.

What this concept proposes for Bloom

Keep two fixed entries above the history: All branch changes and Uncommitted changes. Reuse Bloom's existing workspace selection instead of adding Sublime Merge's branches, remotes, and tags sidebar. Use plain commit rows rather than a repository-wide graph.

Bloom already has a “Since commit” scope. That compares a selected commit with today's working tree. It is a different operation from viewing that commit's own patch, and should not be silently relabelled.

Implementation decisions

  • History scope: commits unique to this branch, newest first, with earlier branch commits loaded on demand.
  • Existing “Since commit”: replace it with individual commit review. The owner confirmed that the existing comparison is not used.
  • Merge commits: include them in history and explicitly compare against the first parent.
  • Live updates: preserve the selected commit and file when an agent commits again. Explain when a rebase or amend removes the selected commit.

This is an interactive design example with invented commits and files. No Git operations run from this page. The native implementation is developed separately.
